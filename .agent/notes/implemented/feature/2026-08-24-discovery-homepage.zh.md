# Agent Note: Discovery 首页

Status: implemented

English | [中文](2026-08-24-discovery-homepage.md)

## Problem

首页还是 V2 形态:硬编码 featuredBook() 的主视觉、平铺的 最新更新 列表、
小说库 网格。§10 的板块一个没有,也没有任何老读者召回。

## Decision

首页改为完全由 `getDiscoveryFeed(userId)` 驱动的服务端组件:

- **今日推荐 hero**——today 首位做大卡(书名/分类/章数/简介 + 开始阅读)。
- **继续阅读**——仅登录且有历史时渲染,行内直达 第N章 · P%。
- **热门小说 / 最新更新 / 新书推荐 / 完结好书 / 猜你喜欢**——每个板块是
  一组带标题的 DiscoveryCard 网格(各板块独立列数);空板块静默收起。猜你喜
  欢只在会话 Cookie 解析成功时出现;卡片把分类名作为 推荐理由 徽章。空目录
  时给一条指向 /books 的友好提示。

身份经 `cookies()` 读 `reader_session`(`await`——Next 15 返回 Promise),
再走 getSessionReader 并 try/catch 兜底;匿名访客自然没有 继续阅读 与 猜你
喜欢。全程服务端渲染——每请求一次 feed 调用加一次历史查询,无客户端请求瀑
布。

验证:干净库 CDP 审计 8/8(种子为三本不同热度:连载×3章、沉寂、完结):
hero=热门之书;板块齐全且 匿名无猜你喜欢;连开三次第1章后 热门小说 首卡翻
转为该书(PV→排序在浏览器里实证);登录后首页出现 猜你喜欢;读完并收藏一
本科幻后,首页出现含 第1章 的 继续阅读 与非空 猜你喜欢。typecheck/build 绿。

## Alternatives considered

**客户端拉 feed + 骨架屏。**LCP 更差,还多一跳,而内容本就每请求级变化。

**个性化 hero(用猜你喜欢首位)。**路线图把 今日推荐 定为编辑位顶格;个性
化放在下一板块,对算法属性更诚实。

**保留 featuredBook()。**其「最新发布书」启发式被 today 打分位严格支配;
已从首页移除(函数保留以兼容 API)。

## Consequences

收益:§10 首页端到端落地——PR37/38 记录的信号开始决定读者看到什么,回访读
者第一时间被召回。代价:首页完全动态且按用户不可缓存(当前规模无碍;要上
CDN 得拆匿名变体);feed 每请求对全部已发布书目重算打分——与书架同样的相
关子查询告警,目录到千本级再上物化计数。
