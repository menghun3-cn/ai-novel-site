# Agent Note: Review console UI

Status: implemented

English | [中文](2026-08-23-review-console-ui.md)

## Problem

V3 的审核工作流与自动发布已有服务层函数和 HTTP API
([相关](2026-08-23-publish-scheduler-api.md)),但没有运营者界面:不 curl 就
看不到待审章节,批准要手拼请求,自动发布配置只能改数据库。

## Decision

独立的**审核队列**页 `/admin/review`(侧栏新增入口,红色计数角标由
`admin:review-changed` 窗口事件驱动):待审章节按 FIFO 排列,附书籍链接,
每行提供 批准·立即发布 / 定时 / 驳回。定时弹窗用 datetime-local 输入
(默认下一个整点);驳回弹窗的备注写入章节 `review_note`。成功/错误反馈走
共享 Notice;每个动作都会重派角标事件,侧栏计数始终贴合事实。

书籍详情页在源头接入流程:草稿行新增 送审 图标按钮;被驳回章节就地渲染
备注(`驳回:…` 警示色);编辑弹窗在章节处于 `pending_review` 时禁用状态下拉
(审核动作属于队列,不属于通用编辑器);新增 每日自动发布 卡片往返
`enabled/hour/count` 并只读展示上次运行日期(调度器首次触发前隐藏)。概览
头部新增可点击的 待审核 统计。

验证沿用 CDP 审计:先经真实 API 造数,headless Edge 断言 18 项结构/交互
检查——包括点击 批准·立即发布 后行消失、反馈条出现、角标减一;详情页送审
后角标加一;375px 抽屉与表格容器化;双端零横向溢出。typecheck 与生产构建
全绿。

## Alternatives considered

**把批准/驳回内联进书籍表格。**落选:审核是跨书工作流——主页应跨全部书籍
按提交先后列出工作,单书表格表达不了。

**审核操作用乐观 UI 更新。**本轮落选:批准不可逆地改变发布状态(首发时间
戳);经 API 重载让 UI 真值与服务端真值恒等,代价可忽略。

**角标计数轮询。**落选:动作后显式事件让数字精确且无后台噪音;仅当另一运营者
并发操作时角标短暂滞后,单运营者控制台可接受。

**独立的驳回原因页/历史。**延后:备注挂在章节上,在生产者要处理它的地方就地
可见;多审核者并存的审计日志属于 V3 之后。

## Consequences

收益:V3 全链路——写作→送审→审核→定时/发布→autopilot 配置——全程可在
浏览器完成,侧栏角标成为常驻的剩余工作量指示。代价:角标在每次导航与本页
动作后各取一次,并发运营者的变更要到下次导航才可见;定时弹窗默认值信任
客户端时钟(服务端无论如何都校验 ISO 字符串)。
