# 1. 项目概述

## 1.1 项目目标

建设一个完整的 AI 小说创作与质量评审系统。

系统包含两个核心能力：

1. **AI 创作中心**
2. **AI 短篇小说自动评审专家**

系统最终形成完整闭环：

```text
用户输入创作需求
        ↓
AI建议 / AI生成 / AI优化
        ↓
生成小说
        ↓
AI自动评审
        ↓
质量评分
        ↓
┌───────────────┐
│ 是否达到质量标准 │
└───────┬───────┘
        │
   ┌────┴────┐
   ↓         ↓
  通过       未通过
   ↓         ↓
保存/发布   AI自动优化
             ↓
          再次评审
             ↓
          通过/失败
```

同时积累所有小说、评审、规则、Prompt、模型数据，为后续 AI 评审规则和 Prompt 持续优化提供数据基础。

---

# 2. 核心设计原则

## 2.1 AI优先

所有需要用户输入的主要字段，都应该提供 AI 辅助能力：

- AI建议
- AI生成
- AI优化

不能只在“生成小说”按钮上体现 AI。

---

## 2.2 自动化优先

小说生成完成后，应自动进入 AI 评审流程。

用户不需要手动点击：

> “开始评审”

默认流程：

```text
生成完成
→ 自动评审
→ 自动判断
→ 不合格自动优化
→ 再评审
```

---

## 2.3 可追溯

任何一次 AI 评审都必须能够追溯：

- 小说来源
- 小说版本
- 评审规则版本
- Prompt版本
- AI模型
- 模型版本
- 评审结果
- 优化次数
- 评审时间

---

## 2.4 全部版本化

以下内容必须支持版本：

- 小说
- 小说内容
- 评审规则
- 评审Prompt
- AI模型配置
- 评审结果

任何历史数据不能因为规则升级而被覆盖。

---

## 2.5 数据驱动优化

评审系统不是一次性写死。

系统需要能够基于历史评审数据：

```text
历史小说
+
历史评审结果
+
优化结果
+
规则版本
+
Prompt版本
```

分析：

> 当前评审标准是否准确？

为未来优化评审规则和 Prompt 提供数据基础。

# 7. AI生成

根据当前字段内容生成完整内容。

例如：

```text

```

AI生成结果必须允许：

- 使用
- 编辑
- 重新生成

# 8. AI优化

用户已经输入内容后，可以点击：

```text
AI优化
```

AI不得无意义地完全重写。

默认要求：

1. 保留用户核心意图
2. 保留已有重要信息
3. 修复逻辑问题
4. 提升表达
5. 增强故事性
6. 给出优化后的内容

同时提供：

```text
原内容
优化后
```

方便用户对比。

# 12. 自动评审流程

```text
小说生成完成
      ↓
创建AI评审任务
      ↓
读取小说内容
      ↓
读取当前生效评审规则
      ↓
读取当前生效Prompt
      ↓
调用AI模型
      ↓
结构化输出评审结果
      ↓
计算最终质量评分
      ↓
判断是否达到质量标准
```

---

# 13. 评审维度

默认规则 v1.0：

| 维度 | 权重 |
|---|---:|
| 故事完整性 | 20% |
| 情节与冲突 | 20% |
| 人物塑造 | 15% |
| 逻辑合理性 | 15% |
| 情绪感染力 | 10% |
| 语言表达 | 10% |
| 创意与独特性 | 10% |
| 总计 | 100% |

权重不能写死在代码中。

必须来自：

```text
评审规则版本
```

---

# 14. 每个维度必须有评分标准

例如：

## 故事完整性

### 90-100

故事结构完整：

- 开端明确
- 冲突成立
- 发展自然
- 高潮有效
- 结局完整
- 前后具有呼应

### 70-89

故事基本完整，但部分结构存在不足。

### 60-69

故事存在明显缺失。

### 0-59

故事结构严重不完整。

其他评审维度同样需要配置：

- 定义
- 评分标准
- 加分条件
- 扣分条件
- 评审说明

# 18. AI评审意见

必须包含：

## 优点

例如：

- 故事结构完整
- 冲突建立自然
- 高潮具有情绪释放

## 问题

例如：

- 配角人物较单薄
- 中段节奏略快
- 结局缺少意外性

## 优化建议

例如：

> 增强配角动机，并增加高潮前的铺垫。

如果：

```text
score >= quality_threshold
```

则：

```text
评审通过
```

如果：

```text
score < quality_threshold
```

则：

```text
自动进入AI优化
```

---

# 20. AI自动优化

AI读取：

```text
原小说
+
评审结果
+
评审问题
+
优化建议
```

然后针对问题进行修改。

不得无理由重新生成完全不同的小说。

默认要求：

- 保留主题
- 保留主要人物
- 保留核心剧情
- 保留用户核心创作意图
- 针对评审问题优化

---

# 21. 自动再评审

优化完成：

```text
AI优化
 ↓
保存新小说版本
 ↓
AI再次评审
```

例如：

```text
V1
72分
↓
AI优化
↓
V2
81分
↓
通过
```

每次优化都必须生成新的小说版本。

不能覆盖原版本。

---

# 22. 最大优化次数

默认：

```text
max_auto_optimize_rounds = 3
```

例如：

```text
第一次生成：72
第一次优化：78
第二次优化：84
```

达到80分后停止。

如果：

```text
72
→ 75
→ 74
→ 77
```

达到最大次数：

```text
自动优化失败
```

进入：

```text
低质量内容池
```

# 31. 评审规则自动优化流程

```text
历史数据
    ↓
AI分析
    ↓
发现评审问题
    ↓
生成规则优化建议
    ↓
生成新规则版本
    ↓
历史数据回归测试
    ↓
与旧版本比较
    ↓
人工确认
    ↓
发布新版本
```

注意：

> AI可以提出和生成新规则，但不能默认直接替换生产规则。

新规则必须经过测试和发布。

# 32. 回归测试

新规则发布前，使用历史小说进行测试。

例如：

```text
测试集：1000篇历史小说

规则 v1.0
平均评分：78.2

规则 v1.1
平均评分：80.1
```

同时比较：

- 平均评分
- 各维度评分
- 通过率
- 优化次数
- 评分稳定性
- 与人工结果的一致程度（如果存在人工结果）

```text
AIProvider
    ↓
Model
    ↓
Generate
```

```text
DeepSeek
GPT
Claude
其他兼容模型
```

# 37. 结构化输出

AI评审必须使用结构化输出。

优先使用：

```text
JSON Schema
```

确保：

- score为数字
- level为固定枚举
- qualified为boolean
- dimensions为数组
- 每个维度必须存在score
- 不允许AI返回无法解析的数据

如果结构化输出失败：

```text
自动重试
```

默认最多：

```text
2次
```

# 47. 产品级验收标准

## AI创作

- 所有主要输入字段都有AI辅助能力
- AI建议可以直接采用
- AI生成结果可以编辑
- AI优化不会无理由破坏用户原始内容
- 小说生成失败有明确提示
- 小说历史版本不会丢失

## AI评审

- 小说生成完成后自动评审
- 不需要人工点击开始评审
- 评审规则可以版本化
- Prompt可以版本化
- 评分维度可以配置
- 权重可以配置
- 质量阈值可以配置
- AI输出必须结构化
- 每次评审必须保存完整记录

## 自动优化

- 低于阈值自动进入优化
- 优化后自动重新评审
- 每次优化产生新版本
- 达到阈值自动停止
- 达到最大次数自动停止
- 不允许无限循环

## 数据追溯

任何评审结果必须能够回答：

```text
评审的是哪一本小说？
小说哪个版本？
小说源地址是什么？
使用了哪个规则？
规则是什么版本？
使用了哪个Prompt？
Prompt是什么版本？
使用了哪个模型？
模型是什么版本？
这是第几次评审？
经过几次优化？
最终评分是多少？
为什么得到这个评分？
```

如果以上任何一个问题无法回答，则评审数据系统不合格。

# 50. 最终目标

最终产品不是简单的：

> AI写小说

而是：

```text
┌──────────────────────────┐
│       AI小说创作中心       │
│                          │
│ 长篇小说 | 短篇小说        │
│                          │
│ AI建议 / AI生成 / AI优化   │
└────────────┬─────────────┘
             ↓
        AI生成小说
             ↓
┌──────────────────────────┐
│      AI短篇小说评审专家     │
│                          │
│ 自动评分                  │
│ 自动判断                  │
│ 自动发现问题              │
└────────────┬─────────────┘
             ↓
        是否达到标准？
        ↙           ↘
      是             否
      ↓              ↓
     入库         AI自动优化
                     ↓
                  再评审
                     ↓
                   入库
                     ↓
              历史评审数据
                     ↓
             AI评审优化专家
                     ↓
          新规则 / 新Prompt
                     ↓
                回归测试
                     ↓
               新版本发布
```

核心理念：

> **AI负责创作，AI负责评审，AI负责发现问题，AI负责优化；系统负责记录、版本化、验证和持续进化。**

最终建立一个可以持续提高小说生成质量和评审质量的 **AI文学创作质量闭环系统**。

# 51. 开发执行原则

AI IDE执行本规格书时：

1. 不得只完成静态UI。
2. 必须实现真实数据流。
3. 必须实现AI任务状态管理。
4. 必须实现小说版本管理。
5. 必须实现评审规则版本管理。
6. 必须实现Prompt版本管理。
7. 必须实现自动评审。
8. 必须实现自动优化和再次评审。
9. 必须保存完整评审链路。
10. 不得覆盖历史评审数据。
11. 不得覆盖历史小说版本。
12. 不得把评审规则硬编码。
13. 不得把模型厂商硬编码到业务逻辑。
14. 必须为后续多模型、多规则、多Prompt实验预留能力。
15. 所有新增功能必须保持现有系统功能正常。

**开发目标不是完成几个页面，而是完成一套可运行的 AI 小说创作与自动质量评审系统。**
